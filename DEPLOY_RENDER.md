# Deploy the Go backend on Render

The repository includes `render.yaml` for the backend Web Service. Render builds from `backend/`, binds to its public port, and checks `/api/health` after deployment. Database migrations run when the Go service starts.

## Deploy

1. Push this repository and `render.yaml` to GitHub.
2. In Render, create a **Blueprint** and connect this repository. Review the `otakuhub-api` service and deploy it.
3. During Blueprint setup, enter `DATABASE_URL`, `ADMIN_USERNAME`, and `CORS_ALLOWED_ORIGINS` when prompted. `JWT_SECRET` is generated by Render.
4. Choose a PostgreSQL provider. You can use Render Postgres or a PostgreSQL integration from Vercel Marketplace. Copy its connection URL into Render's `DATABASE_URL` environment variable. Keep the database URL private.
5. Set `CORS_ALLOWED_ORIGINS` to the exact Vercel site origin, for example `https://otakuhub.vercel.app` (no trailing slash). Add other trusted origins as a comma-separated list if needed.
6. When Render reports the service is live, check `https://<service>.onrender.com/api/health`.
7. In Vercel Project Settings → Environment Variables, set `NEXT_PUBLIC_API_URL` to `https://<service>.onrender.com/api`, then redeploy the frontend.

The frontend calls Render directly over HTTPS. The backend only allows browser origins listed in `CORS_ALLOWED_ORIGINS`; local development defaults to `http://localhost:3000`.

## Database connection

The backend accepts a full PostgreSQL `DATABASE_URL`. If you use Render Postgres, prefer its internal connection URL and place the database and Web Service in the same region. If you use a database outside Render, use its TLS-enabled connection URL. The old `DB_HOST`/`DB_PORT`/`DB_USER`/`DB_PASSWORD` settings are still supported; use `DB_SSLMODE` for the provider's required SSL mode.

For production, choose a Render service plan that fits your traffic. The Blueprint currently uses Render's free web plan for an initial deployment; free web services can spin down when idle. Database plan and billing are selected separately from this Blueprint.

## Local development

Copy `backend/.env.example` to `backend/.env` and set local PostgreSQL credentials. `BIND_ADDRESS` defaults to `127.0.0.1` locally; `render.yaml` sets `0.0.0.0` for Render.
